# Art assets

| Folder | Contents | Edited? |
| --- | --- | --- |
| `assets/source/` | Original files exactly as supplied by the artist | **Never edit or overwrite** |
| `assets/processed/` | Upload-ready copies generated by `scripts/assets/process_card_art.py` | Regenerate; don't hand-edit |

The game never reads these files directly. Roblox can only display images that have been
**uploaded to Roblox** and have an image asset id. Every image the game uses is listed once,
in `src/shared/Config/Assets.luau`, with its source file, processed file and `AssetId`
(`0` = not uploaded yet). `src/shared/Logic/CardArt.luau` resolves a card's or pack's
`Artwork` key through that table. Until an id is filled in, the inventory, reveal screen and
3D stands draw a placeholder card automatically.

### Findings

- **The transparency is real.** Every file has a true alpha channel with fully transparent
  corners (alpha 0) around the rounded card or pack shape. There is **no baked-in
  checkerboard** or background. The processing script verifies this and stops if a corner is
  not transparent.
- **The card art is a complete printed card**, not a bare ferret illustration. Each image
  includes the frame, rarity label, name, subtitle, income and number. The game therefore
  shows the image as-is (`Config.Assets.FullCardArt = true`) instead of drawing its own frame
  around it, and the card definitions copy the printed name, rarity, income, subtitle and
  number. **If the art changes, update `Config/Cards.luau` to match.**
- **Five card images are slightly see-through.** In Sandy, Boba, Sky, Kingston and Aurora,
  the card body sits at alpha 251–253 instead of 255. That's invisible to the eye, but in the
  3D world it sends the image down Roblox's transparent render path, which can cause sorting
  flicker. The processed copies snap alpha ≥ 250 to 255 and keep the anti-aliased edges.
  Frost and the pack front are already clean.
- **The pack front shows the logo "FERRET FRENZY",** while the game's title in the
  specification is "Ferret Card Tycoon". This is flagged for the owner (STATUS.md, Q15). The
  art was not changed.

**Why 1024 px:** Roblox downsamples uploaded images to at most 1024 px on the longest side,
so larger files only waste upload size and memory. The game displays the art at a fraction
of that size: about 150×225 px in the backpack, and a 4.2×6.3-stud billboard on stands.

## Uploading the art to Roblox (manual, required once)

The cloud development environment can't sign in to Roblox, so these steps must be done by
the project owner in Roblox Studio. **Never invent asset ids.**

1. Open the game's place in Roblox Studio. It must be published to Roblox, so that assets
   belong to the game's owner (user or group).
2. Open *View → Asset Manager → Images*, and click **Bulk Import** (the upload icon).
3. Select the **seven files in `assets/processed/pack1/`**, not the originals.
4. Wait for the upload and moderation to finish. Each image appears in the Images list.
5. For each image, right-click it and choose **Copy ID to Clipboard**. The number copied is
   the image asset id.
6. Paste each number into `src/shared/Config/Assets.luau` as the third argument of that
   image's `image(...)` call (for example the `["card.pack1.sandy"]` entry for
   `card_001_sandy.png`). Use `0` for an image that isn't uploaded yet.
7. Run `./scripts/check.sh` (ConfigCheck rejects malformed ids), then press Play. The
   backpack, reveal screen, pack shop and floating stand illustrations now show the real
   art. Studio's Output lists every image as `[Art] <key>: AssetId <id> -> rbxassetid://<id>`,
   warns when a placeholder is drawn instead (and why), and warns when an image fails to
   load (for example a decal id instead of the image id).

**Pack 1 status:** all seven images are uploaded and their ids are set in `Config/Assets.luau`.

Alternative: upload through the Creator Dashboard under *Development Items → Decals*. In
that case, use the **image** id, not the decal id. In Studio, insert the decal and copy the
`Texture` property's number, because a decal id doesn't work as an image.

## Adding art for a new card or pack

1. Put the original file under `assets/source/<Set name>/`.
2. Add a line to `MAPPING` in `scripts/assets/process_card_art.py`, then run the script.
3. Add an entry to `Config/Assets.luau` with `AssetId = 0`, and set the card's or pack's
   `Artwork` to its key.
4. Upload as described above and fill in the id. `tests/unit/CardArt.spec.luau` shows how
   to test the mapping.
